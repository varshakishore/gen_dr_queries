Most productivity studies on tools like GitHub Copilot and Cursor confound **three distinct variables**: (a) base programming expertise, (b) the tool's intrinsic capability, and (c) the user's skill at formulating effective prompts. ## 4. The Hidden Cost: Prompting Overhead and the Productivity Paradox

Even when better prompts yield better single-turn outputs, **the full-cycle cost of prompt engineering skill may absorb or even exceed the gains**. This is one of the most important empirical findings in the recent literature.

## 6. What Specific Prompt Engineering Sub-Skills Matter

The evidence most clearly identifies the following **isolable skill components** as having a non-trivial causal effect on output quality, holding the user and task constant:

| Skill Component | Evidence |
|---|---|

| **Edge-case articulation** | Zi et al. (2025); Fagadau et al. (2024) |
| **Task decomposition / step-wise breakdown** | Zi et al. (2025); GitHub best-practice docs |

## 7. The Skill Acquisition Paradox

One of the most underappreciated findings is that **using AI tools does not automatically develop prompt skill over time**; in fact, the opposite may occur. AI use impairs conceptual understanding, code reading, and debugging abilities, without delivering significant efficiency gains on average; participants who fully delegated coding tasks showed some productivity improvements, but at the cost of learning the library; six distinct AI interaction patterns were identified, three of which involve cognitive engagement and preserve learning outcomes even when participants receive AI assistance. This is a critical dynamic: if prompt engineering skill is partly downstream of deep programming expertise, and AI use impairs the acquisition of that expertise, then prompt skill itself may be a **self-eroding resource** if tools are relied on too heavily early.

## 8. Summary: What Can Be Said About the Isolated Causal Effect

Synthesizing across the evidence, the best current answer to your question is:

1. **The causal effect of prompt engineering skill on *output quality* (per turn) is real but bounded.** Specific sub-skills — I/O precision, edge-case coverage, task decomposition, example provision — have statistically significant and replicable positive effects on code correctness and documentation quality, independent of who is using the tool. Effect sizes in controlled studies range from roughly +10–30% on pass@1 metrics depending on task type and baseline prompt quality.

2. **The causal effect on *net wall-clock productivity* is ambiguous, and may be negative for experienced developers.** The METR study is the most rigorous evidence here: even skilled users of tools like Cursor experienced a 19% slowdown, consistent with the hypothesis that prompting overhead, review burden, and cognitive interruption absorb or exceed the per-turn quality gain.

3. **Prompt skill has a strong interaction with task type.** The extent of improvement varies across task type and complexity, developer expertise, and organizational contexts. [1]Usage, Effects and Requirements for AI Coding Assistants in the Enterprise: An Empirical StudyWhile productivity advantages are clear, the extent of improvement varies across tasks type and complexity (Wang et al., 2024), developer expertise (G... The marginal return to prompt skill is highest for novel, specification-heavy, or domain-unfamiliar tasks, and lowest (or negative) for tasks the developer already knows well — a near-perfect restatement of comparative advantage.

4. **The largest identifiable residual from "pure" prompt skill (net of programming expertise) is the ability to minimize iterative rounds** — that is, to elicit a correct or near-correct output on the first or second interaction rather than through many back-and-forth refinements. 5. **Generic "prompt engineering tips" have non-monotone returns.** Prompt changes should be validated against task-specific test suites rather than assumed beneficial based on conventional wisdom. The fundamental limitation in the literature is that no study has yet fully randomized prompt *skill* (not just prompt *content*) while holding programming expertise, task difficulty, and tool capability constant, largely because prompt skill and programming expertise are not independently assignable in human subjects. This remains the principal open causal identification challenge in the field.
